## Goal

One or two sentences on what should be true when this is done.

## Acceptance criteria

- [ ] A statement you can check by looking at the result
- [ ] One line per case, including the awkward ones

## Out of scope

- Something that does not belong in this task, moved to #TASK-NUMBER

## Constraints

- Files this should stay inside
- Libraries to use
- Guidelines to follow

---

### Grooming notes

- Every acceptance criterion must be **checkable by looking at the result**. If
  you can't point at the screen and say yes or no, rewrite it.
- "Out of scope" is not where you hide things that are hard. If something
  genuinely does not belong here, file a follow-up issue and link it.
- "Constraints" should save the implementer time: which files, which libs, which
  conventions. Not suggestions — hard boundaries.
- The issue must be self-contained. An engineer who has never spoken to the PM
  should be able to implement it from this template and the documents it links.
